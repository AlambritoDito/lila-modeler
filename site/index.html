Lila Modeler
What it does Command line Screenshots Desktop Docs GitHub

Open-source discrete-event simulator and modeler for BPMN processes.

Draw the process, fill in the scenario in the same four steps Bizagi Modeler teaches — validation, times, resources, calendars — and run it. You get Bizagi-style result tables, a replay of the run over the diagram, and an AS-IS versus TO-BE comparison with 95% confidence intervals. Apache-2.0, no account, no server: the same engine runs in the browser, on the desktop, on the command line and behind an MCP server.

The demo is the whole web app running in your browser: it starts with the examples/pedido restaurant process loaded, keeps a copy of your work in the browser's local storage, and opens and saves .bpmn files and .lila projects as ordinary downloads. Nothing is uploaded anywhere.

What it does

One engine, three ways in. The core has no dependencies, so the numbers are the same whether you get them from a browser tab, a terminal or an agent.

  • Model

    A BPMN editor built on bpmn-js: start and end events, timers, tasks, call activities, subprocesses, XOR/OR/AND gateways, lanes and pools — with validation errors and warnings marked on the diagram as you draw.

  • Simulate in four steps

    The Simulate panel follows Bizagi's four levels as four steps: process validation, time analysis, resource analysis and calendar analysis. Arrivals, processing times (the 13 BPSim distributions, the empirical one included, or a constant), resource pools with costs, weekly shift calendars. Scenarios are plain JSON files and can extend one another.

  • Projects

    A project is a folder — model.bpmn, scenarios, results — and a .lila file is that folder zipped. The browser downloads it, the desktop app opens it with a double-click, and the CLI reads the same files.

  • Replications

    Every run is seeded and replicated, so results are reproducible and come with confidence intervals rather than a single lucky number.

  • Results

    Process, element, resource and flow tables in the layout Bizagi Modeler users already read, plus Lila's own extras: ranked bottlenecks, percentiles and cost per case. Export to CSV or to a multi-sheet XLSX workbook.

  • Animate

    Replay the event log of a run over the diagram: a live counter on every task, gateway and end event, tokens walking the flows, the pools' occupancy and a simulated clock, from 1× to instant. No re-run, no second engine.

  • Compare AS-IS vs TO-BE

    Put two or more simulated scenarios side by side, with per-metric deltas and a marker on the differences that are significant at 95% confidence.

  • Routing on earlier outcomes

    A flow out of an exclusive gateway can take a different probability depending on which flow the same case took earlier — the "already rejected once" kind of rule — without splitting the diagram.

  • Themes and languages

    Eva-01 (dark) and Papel (light) ship with the app; a theme is a JSON file you can edit or add. The interface is available in English and Spanish.

  • CLI and MCP

    lila validate, lila run and lila compare for scripts and CI, with JSON, CSV and XLSX output — and lila mcp, an MCP server that hands the same five tools to an agent.

Simulate the benchmark in 3 commands

examples/pedido is the repo's reference benchmark: a restaurant process with a parallel branch, an approval and a timer, with the AS-IS and TO-BE scenarios already written. Clone the repo, run npm ci and npm run build, and:

1Validate the model

npx lila validate examples/pedido/model.bpmn

2Simulate the AS-IS scenario

npx lila run \
  examples/pedido/model.bpmn examples/pedido/as-is.scenario.json \
  --seed 42 --replications 3 \
  --json out/result.json --csv out/csv

3Compare AS-IS against TO-BE

npx lila compare \
  examples/pedido/model.bpmn \
  examples/pedido/as-is.scenario.json examples/pedido/to-be-3-cajeros.scenario.json \
  --seed 42 --replications 3

Lila is not published to npm (the lila package on the registry is an unrelated project): inside the checkout, after npm ci and npm run build, npx resolves the workspace's own binary with no registry lookup and no global install.

Desktop beta

The same app packaged with Electron: projects live as folders on your disk, .lila and .bpmn files open with a double-click, and a welcome screen lists your recent projects. The beta is built for macOS on Apple Silicon and is not signed or notarized: on first launch, right-click the app and choose Open. The beta guide walks through installing it and reading the results.
