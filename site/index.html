Open-source discrete-event simulator and modeler for BPMN processes.

Draw the process, fill in the scenario in the same four steps Bizagi Modeler teaches — validation, times, resources, calendars — and run it. You get Bizagi-style result tables, a replay of the run over the diagram, and an AS-IS versus TO-BE comparison with 95% confidence intervals. Apache-2.0, no account, no server: the same engine runs in the browser, on the desktop, on the command line and behind an MCP server.

The demo is the whole web app running in your browser: it starts with the examples/pedido restaurant process loaded, keeps a copy of your work in the browser's local storage, and opens and saves .bpmn files and .lila projects as ordinary downloads. Nothing is uploaded anywhere. See Getting started for colleagues below for the full flow.

What it does

One engine, three ways in. The core has no dependencies, so the numbers are the same whether you get them from a browser tab, a terminal or an agent.

  • Model

    A BPMN editor built on bpmn-js: start and end events, timers, tasks, call activities, subprocesses, XOR/OR/AND gateways, lanes and pools — with validation errors and warnings marked on the diagram as you draw.

  • Simulate in four steps

    The Simulate panel follows Bizagi's four levels as four steps: process validation, time analysis, resource analysis and calendar analysis. Arrivals, processing times (the 13 BPSim distributions, the empirical one included, or a constant), resource pools with costs, weekly shift calendars. Scenarios are plain JSON files and can extend one another.

  • Projects

    A project is a folder — model.bpmn, scenarios, results — and a .lila file is that folder zipped. The browser downloads it, the desktop app opens it with Open (File menu) or a Finder double-click (verified for Beta 1 through the macOS open-file route; see the beta guide), and the CLI reads the same files.

  • Replications

    Every run is seeded and replicated, so results are reproducible and come with confidence intervals rather than a single lucky number.

  • Results

    Process, element, resource and flow tables in the layout Bizagi Modeler users already read, plus Lila's own extras: ranked bottlenecks, percentiles and cost per case. Export to CSV or to a multi-sheet XLSX workbook.

  • Animate

    Replay the event log of a run over the diagram: a live counter on every task, gateway and end event, tokens walking the flows, the pools' occupancy and a simulated clock, from 1× to instant. No re-run, no second engine.

  • Compare AS-IS vs TO-BE

    Put two or more simulated scenarios side by side, with per-metric deltas and a marker on the differences that are significant at 95% confidence.

  • Routing on earlier outcomes

    A flow out of an exclusive gateway can take a different probability depending on which flow the same case took earlier — the "already rejected once" kind of rule — without splitting the diagram.

  • Themes and languages

    Five themes ship with the app: Eva-01 (dark, the default), Papel (light), Tieso (light, ITESO blues), Akira (dark, Neo-Tokyo) and Montana (purple, bubblegum pink and gold, inspired by Hannah Montana Linux). Your choice persists across sessions. A theme is a JSON file you can edit or add. The interface is available in English and Spanish.

  • CLI and MCP

    lila validate, lila run and lila compare for scripts and CI, with JSON, CSV and XLSX output — and lila mcp, an MCP server that hands the same five tools to an agent.

Simulate the benchmark in 3 commands

examples/pedido is the repo's reference benchmark: a restaurant process with a parallel branch, an approval and a timer, with the AS-IS and TO-BE scenarios already written. Clone the repo, run npm ci and npm run build, and:

1Validate the model

npx lila validate examples/pedido/model.bpmn

2Simulate the AS-IS scenario

npx lila run \
  examples/pedido/model.bpmn examples/pedido/as-is.scenario.json \
  --seed 42 --replications 3 \
  --json out/result.json --csv out/csv

3Compare AS-IS against TO-BE

npx lila compare \
  examples/pedido/model.bpmn \
  examples/pedido/as-is.scenario.json examples/pedido/to-be-3-cajeros.scenario.json \
  --seed 42 --replications 3

Lila is not published to npm (the lila package on the registry is an unrelated project): inside the checkout, after npm ci and npm run build, npx resolves the workspace's own binary with no registry lookup and no global install.

Desktop beta

The same app packaged with Electron: projects live as folders on your disk, .lila and .bpmn files open with a double-click (the .lila open-file route was verified for Beta 1; a physical Finder double-click and .bpmn that way were not; see the beta guide), and a welcome screen lists your recent projects. Beta 1 (v1.0.0-beta.1) attaches a single installer, for macOS on Apple Silicon (arm64); Windows and Linux builds exist only as untested CI artifacts and are not offered for Beta 1. The app is not signed or notarized: on first launch, go to System Settings ▸ Privacy & Security ▸ Open Anyway after the first blocked attempt, then confirm Open (on older macOS, Control-click the app ▸ Open ▸ Open works directly). Do not disable Gatekeeper to work around this. (First-launch flow verified for Beta 1 on macOS 27: the blocked first launch and the Open Anyway step.) The beta guide walks through installing it, checksum verification and reading the results.

Getting started for colleagues

You got a link to this page. Here is the whole flow, and what to expect.

1Try it

Open the demo — it starts with the neutral examples/pedido restaurant process already loaded. Draw or edit a model, open Simulate and run the AS-IS and TO-BE scenarios (already written for the example), then open Compare to see the deltas, and Animate to replay the run over the diagram.

2Know where your work lives

While you work, the browser keeps a copy in that browser's local storage only — clearing site data, or opening the demo in another browser or profile, loses it. That local copy is not a backup. To keep your work anywhere else, use File ▸ Save (tooltip: Save project): it downloads the whole project — model, scenarios, revisions and saved runs — as one portable .lila file.

3Send a project to a colleague

Send them the .lila file (email, chat, a shared drive — anything that moves a file). They open it with File ▸ Open (tooltip: Open project) in the web demo, File ▸ Open project… in the desktop app, or by double-clicking it in Finder (verified for Beta 1 through the macOS open-file route; see the beta guide). This is sharing as portable project files, not simultaneous editing: there is no account, no backend and no real-time collaboration — one person edits a copy at a time, and the last .lila sent around is the one everyone should work from next.

Known limits

  • Single-user filesSharing means passing a .lila around, not co-editing one.
  • No accounts, backend or real-time syncEverything runs locally, in your browser or the desktop app.
  • Mobile editing is untestedBeta 1 acceptance ran on desktop browsers at 1440×900; narrower editor viewports and mobile editing are untested.
  • The macOS beta is unsignedSee the desktop section above for the first-launch steps.

Beta 1 was tested on macOS 27 with Chrome 154; Safari and other browsers are untested. Found a reproducible problem? Open an issue — the bug template asks for a minimal .bpmn file or scenario that shows it.

En español

Llegaste a esta página por un enlace. Así es el flujo completo, y qué esperar.

1Pruébalo

Abre la demo — arranca con el proceso neutral del restaurante, examples/pedido, ya cargado. Dibuja o edita un modelo, abre Simular y corre los escenarios AS-IS y TO-BE (ya escritos para el ejemplo), luego abre Comparar para ver las diferencias, y Animar para reproducir la corrida sobre el diagrama.

2Dónde vive tu trabajo

Mientras trabajas, el navegador guarda una copia solo en el almacenamiento local de ese navegador — borrar los datos del sitio, o abrir la demo en otro navegador o perfil, la pierde. Esa copia local no es un respaldo. Para guardar tu trabajo en cualquier otro lugar, usa Archivo ▸ Guardar (tooltip: Guardar proyecto): descarga el proyecto completo — modelo, escenarios, revisiones y corridas guardadas — como un único archivo .lila portable.

3Enviar un proyecto a un colega

Envíale el archivo .lila (correo, chat, un drive compartido — cualquier cosa que mueva un archivo). Lo abre con Archivo ▸ Abrir (tooltip: Abrir proyecto) en la demo web, Archivo ▸ Abrir proyecto… en la app de escritorio, o con doble clic en el Finder (verificado en la Beta 1 por la ruta open-file de macOS; ver la guía de la beta). Esto es compartir archivos de proyecto portables, no edición simultánea: no hay cuenta, ni backend, ni colaboración en tiempo real — una persona edita una copia a la vez, y el último .lila que circuló es el que todos deberían usar después.

Límites conocidos

  • Archivos de un solo usuarioCompartir es pasar un .lila, no coeditar uno.
  • Sin cuentas, backend ni sincronización en tiempo realTodo corre localmente, en tu navegador o en la app de escritorio.
  • La edición en móvil no está probadaLa aceptación de la Beta 1 corrió en navegadores de escritorio a 1440×900; los viewports de editor más angostos y la edición en móvil no están probados.
  • La beta de macOS no está firmadaVer la sección de escritorio arriba para los pasos del primer arranque.

La Beta 1 se probó en macOS 27 con Chrome 154; Safari y otros navegadores no están probados. ¿Encontraste un problema reproducible? Abre un issue — la plantilla de bug pide un archivo .bpmn mínimo o un escenario que lo muestre.
