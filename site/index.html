02 — How it runs

Not one lucky number. Thirty replications.

Every run is seeded and replicated. Each replication drops into the distribution and the confidence interval tightens — same seed, same answer, every time.

  1. L1Validation — every path reaches an end
  2. L2Time — arrivals and processing times
  3. L3Resources — pools, capacity, cost
  4. L4Calendars — weekly shifts

04 — Quick start

Three commands to a benchmark.

Clone, npm ci && npm run build, then validate, run and compare the restaurant example. Or hand the same engine to an agent over MCP.

webOpen the demo in your browser macDownload the desktop beta (Apple Silicon, unsigned) docsRead the documentation
~/lila-modeler 
$ npx lila validate examples/pedido/model.bpmn
✓ model.bpmn — 0 errors

$ npx lila run examples/pedido/model.bpmn \
    examples/pedido/as-is.scenario.json --seed 42 --replications 30
$ npx lila compare … as-is.scenario.json to-be-3-cajeros.scenario.json

06 — FAQ

Questions, answered.

Is Lila Modeler free?

Yes. Apache-2.0, no account, no paid tier. The same engine runs in the browser, the desktop app, the CLI and the MCP server.

Where does my work live?

In the browser's local storage while you work — that is not a backup. File ▸ Save downloads the whole project as a portable .lila file.

Do I need Bizagi?

No. Lila follows the same four-level workflow and result table layout so Bizagi users feel at home, but it is fully independent.

Can two people edit the same project?

Not simultaneously. Sharing means passing a .lila file around; there is no backend and no real-time sync.

Which platforms are supported?

Any modern desktop browser for the web app. The desktop beta ships for macOS on Apple Silicon and is not signed or notarized — see the beta guide for the first launch, and do not disable Gatekeeper.
