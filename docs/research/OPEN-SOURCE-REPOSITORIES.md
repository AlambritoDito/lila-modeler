# Open-source repositories and architecture modelers for Lila Modeler

> Spanish: [Repositorios de código abierto](../es/research/OPEN-SOURCE-REPOSITORIES.md). Research snapshot: 2026-09-26. This is a documentation and source review, not an installed-product test, interoperability certification, or legal opinion.

## Scope and reading rules

Lila's [repository roadmap](../ROADMAP.md) calls for stable catalog objects, references from multiple diagrams, a reverse index, editable tables, process and object Insights, maps, and eventually a self-hosted team service. Today (v1.0.0-beta.25) a project holds one BPMN process, or several as a version 2 repository under `processes/<slug>/`; catalog objects, the reverse index and server capabilities remain planned. The most useful comparison is therefore the *repository contract and user workflow*, not a replacement for Lila's BPMN simulation engine. Lila's [ADR-020](../DECISIONS.md#adr-020--licenses) keeps the core, CLI, MCP, and web under Apache-2.0 and forbids AGPL/LGPL/Camunda License in `packages/*`.

**Verified** below means an official product page, manual, release note, or project repository documents the stated capability. It does **not** mean a Lila round trip or current-edition entitlement was exercised. **Unverified** means the public evidence does not establish the exact capability, open-source availability, or preservation behavior. “Open source” is applied to a named component, not to every product from the same vendor.

## Product profiles

### Archi and coArchi

Archi is an MIT-licensed, Java/Eclipse desktop ArchiMate modeler. Its [manual](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf) makes the object/occurrence split unusually explicit: an element or relationship belongs to a model tree, can appear more than once in one or several views, and each occurrence may have its own visual appearance. Deleting a figure from a view leaves the model object intact. The Analysis tab lists views using an element and its incoming/outgoing model relations. These are direct precedents for Lila's catalog identity, usage lookup, and navigation. The model supports ArchiMate concepts, relationships, user properties, documentation, viewpoints, the Visualiser, and model-tree search; the [5.10 release history](https://www.archimatetool.com/version-history/) records newer documentation and grid work. Archi is **not a BPMN editor**; its ArchiMate business-process concept is not a BPMN process definition.

Archi saves native `.archimate` models and supports [three-file CSV export/import](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf) for elements, relations, and properties with IDs. It also imports and exports the [Open Group ArchiMate Model Exchange XML](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf), including diagrams, but the manual describes that format as interchange rather than a persistence contract. Its generated HTML report has object tables, search, an Analysis view, and a SQL query tab; this is a reporting/query example, **not evidence of in-app bulk table editing**. A separate [Excel export plug-in](https://www.archimatetool.com/plugins/) is offered to supporters, so it should not be counted as a core open-source feature.

For collaboration, the [MIT-licensed coArchi source](https://github.com/archimatetool/archi-modelrepository-plugin) and [plug-in page](https://www.archimatetool.com/plugins/) describe Git-backed sharing, versioning, and conflict resolution; a Git server can be self-hosted. This is asynchronous model collaboration, not proof of authenticated live editing or approval workflow. The same page lists coArchi2 as a rewrite with early-access binaries and missing features; its [MIT source repository](https://github.com/archimatetool/archi-modelrepository-plugin2) explicitly warns against production use. Archi [5.10.0 shipped on 2026-09-03](https://www.archimatetool.com/download/) for Windows, macOS Intel/Silicon, and Linux. No server installation is needed for solo editing.

### Essential Open Source

Essential is an organization-wide, typed EA repository rather than primarily a freehand diagram editor. Its [metamodel reference for Business Process](https://metamodel.enterprise-architecture.org/EA_Class/Business_Layer/Business_Logical/Business_Process_Type/Business_Process.html) names links to activities, roles, applications, and other classes. The [process modeling guide](https://enterprise-architecture.org/university/business-process-modelling/) distinguishes a logical process from an organization-specific physical process and relates the latter to actual applications. The [process/application mapping view](https://enterprise-architecture.org/university/business-process-application-mapping/) and [report-authoring guide](https://enterprise-architecture.org/university/creating-new-reports/) show the pattern: capture facts and typed relations once, then derive maps, catalogs, and analysis views. It is particularly relevant to Lila's process landscapes, organization catalog, and cross-domain Insights. Native BPMN XML editing or round-trip fidelity is **unverified**; Essential process flows should not be treated as BPMN interchange.

The open-source editor is a maintained Protege-based desktop application; the [Viewer](https://github.com/essentialproject/essential_viewer) is a Java web application, and the [Import Utility](https://github.com/essentialproject/essential_import_utility) loads mapped spreadsheet data. The [multi-user installation guide](https://enterprise-architecture.org/university/multi-user-installation/) documents a `.pprj` project plus optional database-backed multi-user editing, Tomcat-hosted Viewer and Import Utility, and backups. Current [download instructions](https://enterprise-architecture.org/products/essential-open-source/essential-os-download/) list a single-user bundle, Java 8, Tomcat 8.5/9, and MySQL/Postgres/SQL Server options for production multi-user mode. This is self-hostable but a materially different runtime and deployment model from Lila's browser/Electron/TypeScript path.

Edition boundaries matter. Essential's [open-source overview](https://enterprise-architecture.org/university/open-source-overview/) says it has the same metamodel and almost all views as Cloud/Docker, but that the web Editors and full REST API suite belong to Cloud/Docker; it also mentions a simple API in Open Source. The [Import Utility instructions](https://enterprise-architecture.org/university/using-the-essential-import-utility/) document spreadsheet mappings for Open Source. Older vendor material claims an Import Utility REST endpoint, but its current scope and authentication were **not verified** here. The [download page](https://enterprise-architecture.org/products/essential-open-source/essential-os-download/) expressly warns that easier data-capture editors, APIs, and security differ from the commercial products. [Essential Docker](https://enterprise-architecture.org/essential-docker/) is self-hosted but requires a subscription and license keys; self-hosted does not imply open source.

The vendor's [licensing page](https://enterprise-architecture.org/about/licensing/) says releases use GPL-3-or-later **or** AGPL-3 as applicable. The [Viewer repository](https://github.com/essentialproject/essential_viewer) identifies GPL-3.0; the Import Utility repository did not present an equally clear license declaration in this review, so its exact distribution license remains **unverified**. The download page lists metamodel 6.21 (2025-10-02), Viewer 6.21.7 (2026-03-02), and Import Utility 2.10.1 (2026-03-23), while the Viewer [GitHub releases](https://github.com/essentialproject/essential_viewer/releases) include 6.21.10 on 2026-04-15. This confirms component-level maintenance but also a download/repository version mismatch to check before a trial.

### Modelio Open Source

Modelio is a GPL-3.0 Java/Eclipse desktop modeling environment with a shared project model, UML and BPMN diagrams, a metamodel API, scripts, and modules. The [open-source repository](https://github.com/ModelioOpenSource/Modelio) documents BPMN/UML integration, XMI exchange for UML, HTML publication, and Jython/Java extension points. Its [project documentation](https://github.com/ModelioOpenSource/Modelio/wiki/Modeler-_modeler_managing_projects_subprojects) distinguishes work models, repositories, and subprojects; UML/BPMN and local modules are included, while ArchiMate requires an installed plug-in. The [metamodel API documentation](https://github.com/ModelioOpenSource/Modelio/wiki/Metamodel_services) describes metaclasses, attributes, and typed dependencies. That is useful design evidence for a registry of object types and relations, though not a TypeScript library ready for Lila.

Modelio's [BPMN import](https://github.com/ModelioOpenSource/Modelio/wiki/Import_BPMN) can retain source IDs or generate new ones, and its [BPMN export](https://github.com/ModelioOpenSource/Modelio/wiki/Export_BPMN) writes `.bpmn`. The official [5.4.1 notes](https://github.com/ModelioOpenSource/Modelio/wiki/Release-541) describe ArchiMate 3.2 exchange fixes, related-element display, and a BPMN lane linked to an ArchiMate collaboration. The [6.2 notes](https://github.com/ModelioOpenSource/Modelio/wiki/Modelio-Release-6.2) add a visual query builder filtering types, properties, and relationships, plus diagram layout and link-navigation changes. These are concrete ideas for Lila's phase-5 saved analysis and phase-6 mixed-model navigation. A visual query is not proof of Lila-style editable model/object tables or Insights dashboards.

The [6.2 open-source release](https://github.com/ModelioOpenSource/Modelio/releases/tag/v6.2.0) is dated 2026-08-26 and lists Windows and Linux archives. A current macOS package for 6.2 is **unverified** on that release page; older releases list other platforms. The Modelio vendor's [licensing page](https://www.modeliosoft.com/fr/29-modelio/licensing.html) names Teamwork Manager as a paid extension, and its [Standalone page](https://www.modeliosoft.com/en/other-solutions/modelio-standalone.html) points teams to Modelio Server. The 6.2 notes mention Teamwork and Reader, but those mentions do **not** establish open-source entitlement. The downloadable ArchiMate extension's exact license and 6.2 availability also need an artifact-level check; [Modelio's own project guide](https://github.com/ModelioOpenSource/Modelio/wiki/Modeler-_modeler_managing_projects_subprojects) says only that it is installed separately. Treat local modeling and BPMN exchange as verified, while a freely self-hosted collaborative stack remains **unverified**.

## Adoption and interoperability recommendations

1. **Borrow the object/view separation, not a persistence file.** Archi gives the clearest documented precedent for one identity across many occurrences and for reverse usage navigation. Lila's v2 catalog should own stable IDs and relationships; BPMN elements should hold typed references. Keep diagram style and placement separate from catalog facts. The exact cross-model/version identity and deletion rules belong in RM-01, with duplicate BPMN IDs and dangling-reference fixtures. [Archi manual](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf); [Lila roadmap](../ROADMAP.md).
2. **Use Essential as a metamodel and derived-view reference.** Its logical-versus-physical process distinction, explicit relation classes, and mapping reports are useful for Lila's organization/application links and Insights provenance. Adopt only the relations needed by an acceptance scenario; importing its entire ontology would add a large modeling burden. Essential's desktop capture and Java web stack do not fit Lila's first browser/desktop milestone. [Process guide](https://enterprise-architecture.org/university/business-process-modelling/); [report guide](https://enterprise-architecture.org/university/creating-new-reports/).
3. **Use Modelio as an interoperability and query test peer.** A synthetic BPMN fixture should round trip through Modelio's `.bpmn` import/export with IDs, extensions, lanes, diagrams, and warnings compared. For future ArchiMate work, separately test the extension's exchange output and license. Its visual type/property/relation query suggests a navigable saved-query model, not a claim that Modelio's query code can be embedded. [Import](https://github.com/ModelioOpenSource/Modelio/wiki/Import_BPMN); [export](https://github.com/ModelioOpenSource/Modelio/wiki/Export_BPMN); [6.2 notes](https://github.com/ModelioOpenSource/Modelio/wiki/Modelio-Release-6.2).
4. **Keep interchange format-specific.** BPMN XML remains Lila's process-diagram boundary; ArchiMate Exchange XML is a future architecture-map boundary, with explicit conversion diagnostics and preservation tests. CSV may seed catalog objects but should never silently establish identity by name. An ArchiMate business process is not a BPMN execution/simulation model. [Archi exchange explanation](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf); [Modelio BPMN exchange](https://github.com/ModelioOpenSource/Modelio/wiki/Import_export_BPMN).
5. **Separate four possible uses.** Studying design and testing standard files require no code dependency. Calling an external installed tool or service needs a versioned integration contract. Reusing source requires per-component license and dependency review. Archi's MIT source is an inspectable Java reference, not a drop-in TypeScript package. Essential's GPL/AGPL variants and Modelio's GPL source should not be proposed for `packages/*` without a deliberate ADR-020 review. This is a project-architecture boundary, not a legal conclusion. [Archi license](https://github.com/archimatetool/archi/blob/master/License.txt); [Essential licensing](https://enterprise-architecture.org/about/licensing/); [Modelio license](https://github.com/ModelioOpenSource/Modelio/blob/master/LICENSE); [Lila ADR-020](../DECISIONS.md#adr-020--licenses).

## Remaining verification gaps

- Run real, small import/export fixtures: ArchiMate Exchange between Archi and Modelio; BPMN XML between Lila and Modelio; document IDs, links, properties, diagrams, extensions, and data loss. Public feature pages cannot establish round-trip fidelity.
- Inspect the exact Essential Import Utility and metamodel distribution licenses, the current simple API/Import Utility endpoint scope, and the Viewer 6.21.10 versus download-page 6.21.7 discrepancy before an integration trial.
- Inspect the exact Modelio ArchiMate extension package and current 6.2 platform artifacts; verify open-source versus paid Teamwork/Reader functionality by edition, not by release-note mentions.
- Measure large repositories, lazy loading, and table editing in Lila's own browser/desktop architecture. No comparative performance claim follows from these manuals or release notes.
