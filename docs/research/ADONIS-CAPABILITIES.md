# ADONIS public capability research for the Lila Modeler roadmap

> Read this in: [Español](../es/research/ADONIS-CAPABILITIES.md).

Reviewed 2026-09-26. This is a documentary survey of BOC Group's public material, primarily the **ADONIS 17.1 BPMS Application Library** user manual. It is not a licensed installation audit, a compatibility test, or a complete export of the vendor metamodel. The [BOC 19.0 documentation](https://docs.boc-group.com/adonis/en/docs/19.0/user_manual/mty-000000/) and [19.0 update page](https://www.boc-group.com/en/adonis/whats-new/) demonstrate later release-specific material; features from different versions must not be combined into a claim about one deployed edition. The current [Lila roadmap](../ROADMAP.md) already covers most broad families below. This note supplies more precise vendor evidence and candidate acceptance questions, without changing roadmap commitments.

## Evidence and entitlement rules

- **Documented user behavior** means a 17.1 user-manual page describes the function in the BPMS Application Library. The installed application library, configuration, system role, license and edition can still change availability. [Method and metamodel](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/amm-000000/), [model types](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/mty-000000/).
- **Administrator/configurable** means the administrator manual describes a setting or customization; it does not establish that every tenant can use it. The [Properties administration page](https://docs.boc-group.com/adonis/en/docs/17.1/admin_page/attrmm-000000/) explicitly says availability depends on the license. [Rights administration](https://docs.boc-group.com/adonis/en/docs/17.1/admin_page/rightswc-000000/) separates content rights from system-role module, metamodel, release and validation rights.
- **Enterprise/license-limited** is used only where the manual says so. The 17.1 [release workflow manual](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/rwf-000000/) explicitly limits model and document workflows to Enterprise and license entitlement. The current [product page](https://www.boc-group.com/en/adonis/) markets Community, Starter, Grow and Individual, whereas the [comparison-of-editions page](https://www.boc-group.com/en/adonis/comparison-of-editions/) uses Community, Starter and Enterprise. Their naming/packaging must be reconciled with a quote or tenant. Critically, extracted HTML from the comparison table loses some visual checkmarks and column alignment. A row's presence is **not** proof of inclusion in a given edition.
- **Add-on/integration** means the vendor identifies a separate module or connected product. The [features page](https://www.boc-group.com/en/adonis/features/) puts simulation, mining, automation and advanced reporting under extensions; [Process Mining Essentials](https://www.boc-group.com/en/marketplace/bpm/adonis-process-mining-essentials/) explicitly calls itself a product extension requiring ADONIS 17.0+. [Marketplace](https://knowledge.boc-group.com/en/marketplace/adonis/) entries are offers, not installed capability.

## 1. Model and object vocabulary

The [17.1 model-type guide](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/mty-000000/) explicitly lists Product Model; Process Landscape; Business Process, Conversation and Choreography Diagrams; Working Environment Model; IT System Model, Use Case Diagram, Document Model and Data Model; Control, Risk and Control Objective Pools; and Cross-Domain Model. Product, Working Environment, IT and Document Models may have subordinate models. Landscapes navigate process hierarchies. Cross-Domain Models admit all object types and relations and can store dependency analysis. **Scope:** documented for the BPMS Application Library, not proof each tenant/edition exposes each type. **Lila:** retain an incremental registry and separate model contracts, as roadmap phases 3–6 propose; do not present every model family as a BPMN element.

The same source names specific objects in context: products/components, processes, organization structure, systems/applications/infrastructure, documents, entities/properties, risks, controls and control objectives. [Search topics](https://docs.boc-group.com/adonis/en/docs/17.0/user_manual/searc-000000/) additionally expose performers, users, units, roles, services, interfaces, operations, attributes, entities, initiatives and performance indicators. These are examples, **not a complete canonical type/attribute/edge list**. An object-type list extracted from a search page may vary by library and release. **Lila:** use the list as candidate discovery fixtures, then approve exact Lila types and permitted relations in individual contracts. Avoid copying vendor-internal names or inventing a full ADONIS schema.

The [17.1 graphical modeling guide](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/objgra-00000/) distinguishes model-local modeling objects from reusable repository objects. It describes connector endpoint restrictions and relation creation from the Explorer or by nesting; behavior depends on the application library. **Lila:** represent definitions and occurrences separately, define allowed endpoints and cardinality, and ensure references survive model moves. **Unverified:** complete endpoint matrix and serialization identifiers.

## 2. Repository, reuse and relationships

The [Explorer manual](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/mamoo-00000/) documents separate Model and Object Catalogues, hierarchical groups, recent/favorite items, search/filter by type, reusable objects in multiple models, and relation creation between objects or objects and models. It also documents replacement/merge behavior and warns on deleting used or referenced objects; its override can still remove them. [Usage Analysis](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/usa-000000/) shows incoming/outgoing, valid/broken references and the models using a repository object. **Lila:** roadmap phase 1's reverse index should support rename, usage, dangling-reference inspection, and deliberate delete/replace policy. Make deletion consequences explicit; do not assume the ADONIS override behavior is desirable. **Unverified:** exact identity/version semantics and conflict behavior require a tenant and export fixtures.

The [17.1 properties manual](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/adinf-00000/) describes model/object attributes and relations as editable properties. [Administration Properties](https://docs.boc-group.com/adonis/en/docs/17.1/admin_page/attrmm-000000/) arranges them in chapters and groups and shows language-independent names, types, mandatory, read-only and default-value controls; relation labels can be localized. **Scope:** administrator editing is license-dependent and some relations may be locked by product customizers. **Lila:** typed forms and relation pickers can derive from Lila's own registry; a draft schema should preserve stable IDs, locale labels and validation metadata. **Unverified:** a complete public export of the default 17.1 library was not found.

The [document-management manual](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/condms-00000/) says uploaded files become Document objects with a referenced-document property, can be used in models, and are included in repository backups/migrations. File types and maximum size are configurable (the manual states up to 50 MB), and language-specific file variants are possible. [Search](https://docs.boc-group.com/adonis/en/docs/17.0/user_manual/searc-000000/) describes full-text document search. **Lila:** phase 2 attachment contract should specify bytes, MIME/type policy, size, integrity and round trips; multilingual assets can be a later explicit choice. **Unverified:** storage API, deduplication and exact backup format.

The [object import/export manual](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/impexpobj-00000/) documents configurable Excel import/update using XML configuration and sample configurations in the BPMS library, plus connected-object synchronization with ADOIT. The [BPMN DI import/export guide](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/bmpndi-00000/) describes BPMN/XML or ZIP import, and optional export of referenced embedded subprocesses and call activities. **Lila:** treat catalog import and BPMN interchange as separate contracts with loss reports. **Unverified:** semantic round trips for customized relations, Lila extensions and vendor extensions; test real files before any parity claim.

## 3. Editing and reading surfaces

The [17.1 tabular editor](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/tab-000000/) renders objects as rows and attributes/relations as columns, for a model or selected catalog objects. It supports cell edit, multi-cell selection, copy/paste within and across tables or Excel, column selection, sorting, adding existing or new objects, and XLSX exports. Inapplicable cells are grey. The manual says multi-cell paste applies **best effort**, ignoring incompatible cells. **Lila:** the roadmap's atomic bulk-edit and undo acceptance is a deliberate Lila quality choice, not observed ADONIS parity; surface errors per cell. **Unverified:** transaction, undo and concurrent-edit behavior in ADONIS.

The [17.1 textual view](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/tex-000000/) orders process steps, descriptions, responsibilities and resources, links to subsequent or referenced objects, allows columns/details controls and XLSX export. The standard BPMS library enables it for Business Process Diagrams; other types depend on configuration. **Lila:** consider a readable work-instruction view beyond editable table and diagram, with navigation and provenance. This is not yet an explicit roadmap row. **Unverified:** whether the text view includes every BPMN path or unsupported notation element.

The [17.1 Insights manual](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/igh-000000/) separates read/analysis dashboards from editable properties. The BPMS library enables them for Business Process Diagrams and repository object types, with object relationship networks, usage, risks/controls, control objectives, timelines and type-specific widgets. Process widgets include hierarchy, SIPOC, RACI, documents, applications/resources, maturity, risks, indicators and initiatives. Empty sections are hidden by default; widgets can be filtered/exported and source artifacts navigated. **Lila:** implement source-linked, typed queries, and distinguish missing from zero. **Scope:** widgets are library/version-dependent; mining-specific variants and directly-follows graph widgets require Process Mining Essentials plus a linked project. **Unverified:** exact calculations of vendor maturity and risk scores, permissions on every drill-down, and widgets in other releases.

The [17.1 chart manual](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/modwv-00000/) documents reusable analysis datasets with bar, nested-box, bubble, Gantt and matrix charts. A matrix can show direct relations or intermediate objects; special BPMS templates include RACI, OMRA, value at risk, initiative progress and control-objective maturity, subject to configuration. Charts can be saved/shared and exported. **Lila:** phase 5 could make saved analysis datasets and relation paths a product concept; an RACI matrix is one preset on top of that. **Unverified:** whether chart templates/editing are available in each current edition.

The [17.1 search/analysis guide](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/searc-000000/) describes search across models, objects and document content, filters by topic/type/property, combined AND/OR criteria and analysis without a text term. [Usage Analysis](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/usa-000000/) and [Dependency Modeller](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/dep-000000/) are complementary graph navigation. The latter creates a swimlane dependency view from incoming/outgoing object relations, with administrator-defined templates. **Lila:** consider saved queries, explicit relation paths and missing-reference filters alongside Explorer search. **Unverified:** indexing latency/performance and tenant access filtering.

## 4. Responsibilities, risk, indicators and governance

The [17.1 process Insights page](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/igh-000000/) confirms a process RACI role table and a matrix shortcut. Role Insights trace Task → RACI relation → Role and show process and model responsibilities; organizational-unit Insights aggregate assigned roles and processes. The [admin concept-of-use page](https://docs.boc-group.com/adonis/en/docs/17.1/admin_page/conwc-000000/) distinguishes **business Role objects** from **system roles** that grant permissions. **Lila:** preserve that distinction; RACI must never imply login access or simulation capacity. **Unverified:** full cardinality and validation rules for RACI.

The [17.1 model-type guide](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/mty-000000/) documents Risk, Control and Control Objective Pools. [Insights](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/igh-000000/) links relevant risks to mitigating controls, shows likelihood, impact, detection, value at risk, owner and required controls, and reports as-is/to-be maturity on control-objective relations. [Charts](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/modwv-00000/) allow risk evaluation in bubble/matrix views. **Lila:** phase 4 needs catalog identities, scoring scale/provenance, control coverage and assessment history. A linked control is not evidence of effectiveness. **Unverified:** exact ADONIS scoring formulas, inherited/residual-risk semantics, and whether advanced GRC requires a module or ADOGRC integration in a particular edition. The [editions page](https://www.boc-group.com/en/adonis/comparison-of-editions/) names GRC modules but its extracted checkmarks do not support per-edition assignment.

The [17.1 Insights process widgets](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/igh-000000/) show Performance Indicator state, current/target values, unit and periodicity, plus initiative state/progress/owner and process maturity attributes. The [17.0 Design & Document scenario](https://docs.boc-group.com/adonis/en/docs/17.0/user_manual/sta-100000/) describes target comparisons and KPI filters by owner/process. **Lila:** roadmap phase 5 should add observed date, measurement type and source, explicitly absent from these summarized widgets. **Unverified:** full indicator measurement schema, historical timeseries, automatic data ingestion and edition entitlement.

The [17.1 release workflow](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/rwf-000000/) documents model drafts, methodical/business review, release, predecessor archiving, version history, change comments and optional validity/prolongation. Default model workflow covers Business Process Diagrams, Process Landscapes and Process objects; documents have a separate workflow. It is explicitly Enterprise/license-dependent and customizable. [Model comparison](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/compa-000000/) highlights model/object/connector/property changes and can compare a version to predecessor. [Validation](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/val-000000/) checks modeling guidance. **Lila:** phase 7 needs independent contracts for version identity, immutable releases, approval authorization, validity and semantic diff. The vendor's documented archive/reference behavior is a test case, not an automatic Lila design choice. **Unverified:** exact audit immutability and tenant-specific workflows.

The [rights administration page](https://docs.boc-group.com/adonis/en/docs/17.1/admin_page/rightswc-000000/) describes user/group permissions for content and system-role rights for functionality and metamodel elements. **Lila:** a future server must enforce write authorization server-side and audit transitions; local owner metadata alone is insufficient. **Unverified:** exact vendor permission inheritance and API authorization cases.

## 5. Modules, integration and newer-version signals

The [17.1 simulation manual](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/sim-000000/) documents cycle-time, cost and resource analysis; the current [vendor features page](https://www.boc-group.com/en/adonis/features/) presents simulation as an extension, and the [optimization offer](https://www.boc-group.com/en/adonis/solution/process-optimization/) calls it an add-on module. Do not equate a manual chapter with base entitlement. **Lila:** preserve existing simulation contracts and compare using explicit inputs/outputs, not marketing labels. **Unverified:** numerical parity or same simulation assumptions.

The [Process Mining Essentials offer](https://www.boc-group.com/en/marketplace/bpm/adonis-process-mining-essentials/) and [17.1 Insights documentation](https://docs.boc-group.com/adonis/en/docs/17.1/user_manual/igh-000000/) place discovered paths, variants, conformance and directly-follows graphs behind a separate add-on and linked mining project. [Integration instructions](https://docs.boc-group.com/adonis/en/processmining/adonis-integration/) distinguish linking by project ID in 17.0/17.1 from direct project selection in 17.2+. **Lila:** roadmap phase 8 should retain observed-event provenance and adapter boundaries. **Unverified:** event schema, source connectors, mining algorithms and licensed packaging.

The [marketplace](https://knowledge.boc-group.com/en/marketplace/adonis/) distinguishes modules, integrations, mobile apps and training. Its listings include Process Portal, Strategy & Performance Management, Word Report Creator, Process Mining Essentials and Process Automation. The [features page](https://www.boc-group.com/en/adonis/features/) also positions Teams/SharePoint/Confluence, ADOIT and ADOGRC as integrations. **Lila:** keep these as separate ecosystem opportunities; do not fold their capabilities into an assumed core baseline. **Unverified:** current pricing, installation prerequisites and data-contract behavior per connector.

The [BOC Developer Portal API overview](https://developer.boc-group.com/adoxx/en/API-introduction/) lists metamodel, repository read/write/search, favorites and user APIs and OpenAPI specification. [Version index](https://developer.boc-group.com/adoxx/en/versions/) groups API documentation by product release. The [official examples repository](https://github.com/BOC-Group/developer-examples) illustrates authenticated calls; the [ADONIS REST API offer](https://knowledge.boc-group.com/en/module/adonis-rest-api/) says activation is needed. **Lila:** phase 8 catalog/model API and MCP should expose explicit authorization, identity and revision rules. **Unverified:** a complete live endpoint/field mapping and availability under any specific subscription.

The [17.1 news](https://docs.boc-group.com/adonis/en/docs/17.1/news/) adds multiple object-type coloring and licensed Properties enhancements. The [18.0 configurable dashboard manual](https://docs.boc-group.com/adonis/en/docs/18.0/user_manual/confda-00000/) and [19.0 product update](https://www.boc-group.com/en/adonis/whats-new/) describe configurable role dashboards and newer AI functions. These are **release-specific signals** for roadmap review, not 17.1 baseline claims. **Lila:** consider configurable dashboard definitions after initial fixed Insights. **Unverified:** actual availability by edition and migration behavior.

## Roadmap review notes

The current roadmap includes the major repository, view, risk, KPI, governance and integration families. The public evidence suggests four items deserve an explicit acceptance decision when their phases are specified: (1) a readable textual process/work-instruction view distinct from table editing; (2) saved cross-object searches and analysis datasets; (3) document release/version behavior distinct from model release; and (4) configurable dashboards as a later option beyond fixed Insights. These are **candidate additions**, not vendor-parity requirements. Preserve Lila-specific decisions such as atomic bulk edits, source/date/kind for metrics and safe cross-model identities even where the ADONIS manual does not promise them.

## Practical verification still needed

1. Obtain a lawful test tenant and record exact ADONIS version, edition/plan, license, application library and enabled modules; inspect actual model/object menus and feature rights. Do not infer checks from the web edition table.
2. Build synthetic fixtures with two processes sharing a role, application, document, risk and control. Test creation, rename, replacement, deletion, usage and broken-reference behavior. Specifically test whether a shared versioned Process object and its references move to a new version when one or both containing models are released; then inspect export/import round trips.
3. Compare graphical, textual, tabular, RACI and Insights views on the same process. Test invalid multi-cell paste, permissions, undo, and how unsupported BPMN constructs appear.
4. Exercise draft/review/release, predecessor comparison, references, validity and document versioning with different user roles, if the license permits.
5. Confirm add-on boundaries for simulation, mining, AI, reporting, portal and integrations with vendor documentation or a quote; test API scopes and authentication only against authorized instances.

All vendor descriptions above are paraphrased. No private schema, proprietary screenshot or unlicensed behavior is represented as observed fact.
