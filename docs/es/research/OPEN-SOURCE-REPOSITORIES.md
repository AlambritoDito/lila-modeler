# Repositorios y modeladores de arquitectura de código abierto para Lila Modeler

> Leer en: [English](../../research/OPEN-SOURCE-REPOSITORIES.md).

Fecha de investigación: 2026-09-26. Es una revisión de documentación y código fuente, no una prueba de productos instalados, certificación de interoperabilidad ni dictamen legal.

## Alcance y criterios de lectura

La [hoja de ruta del repositorio](../ROADMAP.md) de Lila pide objetos de catálogo con identidad estable, referencias desde varios diagramas, índice inverso, tablas editables, Insights de procesos y objetos, mapas y, más adelante, un servicio autohospedado para equipos. Hoy (v1.0.0-beta.26, commit `7dd61e2`) un proyecto contiene un proceso BPMN, o varios como repositorio versión 2 bajo `processes/<slug>/`; los objetos de catálogo, el índice inverso y el servidor siguen planificados. Por ello, la comparación útil es el *contrato del repositorio y el flujo de trabajo*, sin plantear reemplazar el motor de simulación BPMN de Lila. La [ADR-020](../DECISIONS.md#adr-020--licencias) mantiene core, CLI, MCP y web bajo Apache-2.0 y prohíbe AGPL/LGPL/Camunda License en `packages/*`.

**Verificado** significa que una página oficial, manual, nota de versión o repositorio del proyecto documenta la capacidad citada. **No** implica que hayamos ejecutado una ida y vuelta con Lila ni comprobado los derechos de una edición actual. **No verificado** significa que la evidencia pública no establece la capacidad exacta, su disponibilidad en código abierto o la conservación de datos. «Código abierto» se aplica a un componente identificado, no a todos los productos de un proveedor.

## Perfiles de producto

### Archi y coArchi

Archi es un modelador de escritorio ArchiMate, hecho con Java/Eclipse y bajo licencia MIT. Su [manual](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf) separa con claridad objeto y aparición: un elemento o relación pertenece al árbol del modelo, puede aparecer varias veces en una o varias vistas, y cada aparición puede tener un aspecto diferente. Quitar una figura de una vista conserva el objeto. La pestaña de análisis enumera las vistas que usan un elemento y sus relaciones entrantes y salientes. Son referencias directas para la identidad de catálogo, búsqueda de usos y navegación de Lila. El modelo admite conceptos y relaciones ArchiMate, propiedades de usuario, documentación, puntos de vista, Visualiser y búsqueda en el árbol; el [historial de la versión 5.10](https://www.archimatetool.com/version-history/) registra mejoras recientes de documentación y cuadrícula. Archi **no es editor BPMN**; su concepto ArchiMate de proceso de negocio no equivale a una definición de proceso BPMN.

Archi guarda modelos `.archimate` nativos y ofrece [exportación e importación CSV en tres archivos](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf): elementos, relaciones y propiedades con ID. También importa y exporta el [XML de intercambio ArchiMate de The Open Group](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf), incluidos diagramas, aunque el manual lo describe como intercambio, no como contrato de persistencia. El informe HTML generado ofrece tablas de objetos, búsqueda, vista de análisis y una pestaña de consultas SQL: es un ejemplo de informes y consultas, **no prueba de edición masiva de tablas dentro de la aplicación**. Hay un [complemento de exportación a Excel](https://www.archimatetool.com/plugins/) ofrecido a colaboradores económicos; no se debe contar como función básica de código abierto.

Para colaborar, el [código MIT de coArchi](https://github.com/archimatetool/archi-modelrepository-plugin) y la [página de complementos](https://www.archimatetool.com/plugins/) describen uso compartido, versiones y resolución de conflictos sobre Git; el servidor Git puede autohospedarse. Es colaboración asincrónica de modelos, no prueba de edición simultánea autenticada ni de aprobaciones. La misma página presenta coArchi2 como reescritura con binarios de acceso anticipado y funciones pendientes; su [repositorio fuente MIT](https://github.com/archimatetool/archi-modelrepository-plugin2) advierte expresamente que no debe usarse en producción. Archi [5.10.0 salió el 2026-09-03](https://www.archimatetool.com/download/) para Windows, macOS Intel/Silicon y Linux. La edición individual no requiere servidor.

### Essential Open Source

Essential es un repositorio de arquitectura empresarial con tipos para toda la organización, más que un editor de diagramas de dibujo libre. Su [referencia de metamodelo para Business Process](https://metamodel.enterprise-architecture.org/EA_Class/Business_Layer/Business_Logical/Business_Process_Type/Business_Process.html) identifica vínculos con actividades, roles, aplicaciones y otras clases. La [guía de procesos](https://enterprise-architecture.org/university/business-process-modelling/) distingue el proceso lógico del proceso físico realizado por una organización y relaciona este último con aplicaciones concretas. La [vista de mapeo proceso/aplicación](https://enterprise-architecture.org/university/business-process-application-mapping/) y la [guía para crear informes](https://enterprise-architecture.org/university/creating-new-reports/) muestran el patrón: capturar hechos y relaciones tipadas una vez para derivar mapas, catálogos y vistas analíticas. Es especialmente pertinente para los paisajes de procesos, catálogo organizacional e Insights entre dominios de Lila. La edición o conservación de ida y vuelta de XML BPMN nativo está **no verificada**; los flujos de Essential no deben tratarse como intercambio BPMN.

El editor abierto se basa en Protege y funciona en escritorio; el [Viewer](https://github.com/essentialproject/essential_viewer) es una aplicación web Java y la [Import Utility](https://github.com/essentialproject/essential_import_utility) carga datos de hojas de cálculo mediante mapeos. La [guía de instalación multiusuario](https://enterprise-architecture.org/university/multi-user-installation/) documenta un proyecto `.pprj`, edición multiusuario opcional sobre base de datos, Viewer e Import Utility en Tomcat y copias de seguridad. Las [instrucciones de descarga actuales](https://enterprise-architecture.org/products/essential-open-source/essential-os-download/) enumeran un paquete monousuario, Java 8, Tomcat 8.5/9 y opciones de MySQL/Postgres/SQL Server para producción multiusuario. Puede autohospedarse, pero su ejecución y despliegue difieren considerablemente de la ruta navegador/Electron/TypeScript de Lila.

Importa distinguir ediciones. La [descripción de la edición abierta](https://enterprise-architecture.org/university/open-source-overview/) indica que comparte metamodelo y casi todas las vistas con Cloud/Docker, pero que los editores web y la suite REST completa pertenecen a Cloud/Docker; también menciona una API sencilla en Open Source. Las [instrucciones de Import Utility](https://enterprise-architecture.org/university/using-the-essential-import-utility/) documentan mapeos de hojas para Open Source. Material antiguo del proveedor atribuye un endpoint REST a Import Utility, pero su alcance y autenticación actuales quedaron **sin verificar** aquí. La [página de descarga](https://enterprise-architecture.org/products/essential-open-source/essential-os-download/) advierte expresamente diferencias en editores de captura, API y seguridad frente a los productos comerciales. [Essential Docker](https://enterprise-architecture.org/essential-docker/) se autohospeda, pero exige suscripción y claves de licencia; autohospedado no significa de código abierto.

La [página de licencias del proveedor](https://enterprise-architecture.org/about/licensing/) indica GPL-3-o-posterior **o** AGPL-3 según la versión pertinente. El [repositorio Viewer](https://github.com/essentialproject/essential_viewer) identifica GPL-3.0; el repositorio de Import Utility no mostró una declaración de licencia igualmente clara durante esta revisión, por lo que la licencia exacta de su distribución queda **no verificada**. La página de descarga enumera metamodelo 6.21 (2025-10-02), Viewer 6.21.7 (2026-03-02) e Import Utility 2.10.1 (2026-03-23), mientras que las [versiones de GitHub de Viewer](https://github.com/essentialproject/essential_viewer/releases) incluyen 6.21.10 del 2026-04-15. Esto confirma mantenimiento por componente y muestra una discrepancia entre la descarga y el repositorio que conviene comprobar antes de una prueba.

### Modelio Open Source

Modelio es un entorno de escritorio Java/Eclipse bajo GPL-3.0, con modelo compartido de proyecto, diagramas UML y BPMN, API de metamodelo, scripts y módulos. El [repositorio abierto](https://github.com/ModelioOpenSource/Modelio) documenta integración BPMN/UML, intercambio XMI para UML, publicación HTML y puntos de extensión Jython/Java. Su [documentación de proyectos](https://github.com/ModelioOpenSource/Modelio/wiki/Modeler-_modeler_managing_projects_subprojects) distingue modelos de trabajo, repositorios y subproyectos; incluye UML/BPMN y módulos locales, mientras que ArchiMate requiere instalar un complemento. La [documentación de la API de metamodelo](https://github.com/ModelioOpenSource/Modelio/wiki/Metamodel_services) describe metaclases, atributos y dependencias tipadas. Sirve como evidencia de diseño para un registro de tipos y relaciones, aunque no constituye una biblioteca TypeScript lista para Lila.

La [importación BPMN](https://github.com/ModelioOpenSource/Modelio/wiki/Import_BPMN) de Modelio puede conservar los ID de origen o generar otros; la [exportación BPMN](https://github.com/ModelioOpenSource/Modelio/wiki/Export_BPMN) escribe `.bpmn`. Las [notas 5.4.1](https://github.com/ModelioOpenSource/Modelio/wiki/Release-541) describen correcciones del intercambio ArchiMate 3.2, visualización de elementos relacionados y un carril BPMN vinculado a una colaboración ArchiMate. Las [notas 6.2](https://github.com/ModelioOpenSource/Modelio/wiki/Modelio-Release-6.2) añaden un constructor visual de consultas con filtros por tipos, propiedades y relaciones, además de mejoras de distribución y navegación de vínculos. Son ideas concretas para el análisis guardado de la fase 5 y la navegación entre modelos de la fase 6 de Lila. La consulta visual no prueba que existan tablas editables de modelos/objetos o paneles Insights como los de Lila.

La [versión abierta 6.2](https://github.com/ModelioOpenSource/Modelio/releases/tag/v6.2.0) tiene fecha 2026-08-26 y presenta paquetes de Windows y Linux. En esa página, un paquete actual de macOS para 6.2 queda **no verificado**; versiones antiguas muestran otras plataformas. La [página de licencias del proveedor](https://www.modeliosoft.com/fr/29-modelio/licensing.html) identifica Teamwork Manager como extensión de pago, y su [página de Standalone](https://www.modeliosoft.com/en/other-solutions/modelio-standalone.html) remite a los equipos a Modelio Server. Las notas 6.2 mencionan Teamwork y Reader, pero eso **no** demuestra acceso con la edición abierta. También faltan verificar la licencia exacta y disponibilidad para 6.2 del complemento ArchiMate; la [guía de proyectos de Modelio](https://github.com/ModelioOpenSource/Modelio/wiki/Modeler-_modeler_managing_projects_subprojects) solo indica que se instala aparte. El modelado local y el intercambio BPMN están verificados; una pila de colaboración libre y autohospedada sigue **no verificada**.

## Recomendaciones de adopción e interoperabilidad

1. **Tomar la separación entre objeto y vista, sin copiar un archivo de persistencia.** Archi ofrece el precedente más claro de una identidad en varias apariciones y navegación inversa de usos. El catálogo de Lila (repositorio versión 3, [ADR-032](../DECISIONS.md)) debe poseer ID estables y relaciones; los elementos BPMN deben conservar referencias tipadas. El estilo y la posición del diagrama deben separarse de los hechos del catálogo. RM-01 debe fijar la identidad entre modelos/versiones y reglas de eliminación, con casos de ID BPMN repetidos y referencias rotas. [Manual Archi](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf); [hoja de ruta Lila](../ROADMAP.md).
2. **Usar Essential como referencia de metamodelo y vistas derivadas.** Su distinción entre proceso lógico y físico, clases explícitas de relación e informes de mapeo ayudan a diseñar vínculos organización/aplicación e Insights con procedencia. Conviene adoptar solo las relaciones necesarias para un caso de aceptación; importar toda la ontología añadiría una gran carga de modelado. Su captura de escritorio y pila web Java no encajan con el primer hito navegador/escritorio de Lila. [Guía de procesos](https://enterprise-architecture.org/university/business-process-modelling/); [guía de informes](https://enterprise-architecture.org/university/creating-new-reports/).
3. **Usar Modelio como par para probar interoperabilidad y consultas.** Un caso BPMN sintético debe pasar por importación/exportación `.bpmn` de Modelio y comparar ID, extensiones, carriles, diagramas y avisos. Para ArchiMate futuro, hay que probar por separado la salida del complemento y su licencia. Su consulta visual por tipo/propiedad/relación sugiere análisis guardados y navegables; no implica incorporar el código de consultas de Modelio. [Importación](https://github.com/ModelioOpenSource/Modelio/wiki/Import_BPMN); [exportación](https://github.com/ModelioOpenSource/Modelio/wiki/Export_BPMN); [notas 6.2](https://github.com/ModelioOpenSource/Modelio/wiki/Modelio-Release-6.2).
4. **Mantener el intercambio específico por formato.** XML BPMN sigue siendo el límite para diagramas de procesos de Lila; el XML de intercambio ArchiMate sería un límite futuro para mapas de arquitectura, con diagnósticos de conversión y pruebas de conservación. CSV puede alimentar el catálogo, pero no debe establecer identidad silenciosamente por nombre. Un proceso de negocio ArchiMate no es un modelo BPMN de ejecución/simulación. [Explicación de intercambio Archi](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf); [intercambio BPMN Modelio](https://github.com/ModelioOpenSource/Modelio/wiki/Import_export_BPMN).
5. **Separar cuatro usos posibles.** Estudiar el diseño y probar archivos estándar no crean dependencias de código. Llamar a una herramienta o servicio externo exige un contrato de integración versionado. Reutilizar código requiere revisar licencia y dependencias por componente. El código MIT de Archi es una referencia Java inspeccionable, no un paquete TypeScript incorporable directamente. No se deben proponer las variantes GPL/AGPL de Essential ni el código GPL de Modelio para `packages/*` sin revisión deliberada de ADR-020. Es un límite de arquitectura del proyecto, no una conclusión legal. [Licencia Archi](https://github.com/archimatetool/archi/blob/master/License.txt); [licencias Essential](https://enterprise-architecture.org/about/licensing/); [licencia Modelio](https://github.com/ModelioOpenSource/Modelio/blob/master/LICENSE); [ADR-020 Lila](../DECISIONS.md#adr-020--licencias).

## Aspectos pendientes de verificar

- Ejecutar archivos pequeños reales de importación/exportación: XML ArchiMate entre Archi y Modelio; XML BPMN entre Lila y Modelio; documentar ID, relaciones, propiedades, diagramas, extensiones y pérdidas. Las páginas de funciones no prueban fidelidad de ida y vuelta.
- Examinar las licencias exactas de las distribuciones Import Utility y metamodelo de Essential, el alcance actual de la API simple y del endpoint de Import Utility, y la discrepancia Viewer 6.21.10 frente a 6.21.7 de la página de descarga antes de intentar integración.
- Examinar el paquete exacto del complemento ArchiMate de Modelio y los artefactos de plataforma de 6.2; verificar Teamwork/Reader en edición abierta o de pago según la edición, no por menciones en notas de versión.
- Medir repositorios grandes, carga diferida y edición de tablas en la propia arquitectura navegador/escritorio de Lila. Estos manuales y notas no respaldan comparaciones de rendimiento.
