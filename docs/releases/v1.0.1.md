# Lila Modeler 1.0.1

A patch for 1.0.0 with fixes only. Results of models that ran on 1.0.0 are unchanged, and 1.0.0
opens every file 1.0.1 writes. The web app on Pages («Open the stable app»), the desktop
installers below and the `@lila-modeler/engine` and `@lila-modeler/mcp` packages on npm all move
to this version.

## What is fixed

- **A `.lila` keeps what it could not read** (#725, #690). A scenario or run that fails to parse,
  and files the format does not know, used to disappear on the next save or CLI/MCP write. They are
  now kept byte for byte and listed by `lila project show`; a write that would overwrite or orphan
  one is refused with the reason. In the browser they do not survive a page reload yet: save first.
- **A cycle no case can leave is rejected before the run** (#727). With no `run.duration`, a loop
  whose every way out has probability 0 used to exhaust memory; now the lint and the run report
  `E-CICLO-SIN-SALIDA` with the element and the gateway. Endless runs with another cause are not
  detected.
- **Fit in the Model tab** (#717) no longer hides the start of the process under the floating
  toolbars.

The full list is in the
[changelog](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.1/CHANGELOG.md).

## Reporting a problem

If something fails or reads wrong, use **Report a problem…**: on the desktop under **Help**, in the
web app in the app menu, or ⌘K / Ctrl+K and type «report». It opens GitHub's bug form with the
version and your platform already filled in; nothing is sent until you press **Submit**. Attach the
smallest `.lila` or `.bpmn` that shows the problem, and say what you expected.

## Install on macOS (Apple Silicon)

Download `Lila-Modeler-1.0.1-mac-arm64.dmg`, open it and drag the app to Applications. The app
is ad-hoc sealed but **not notarized**, so macOS blocks the first launch: double-click the app once,
then go to **System Settings ▸ Privacy & Security** and click **Open Anyway** next to the message
naming Lila Modeler, and confirm **Open**. On older macOS, Control-click the app ▸ **Open** ▸
**Open** works directly. Do not disable Gatekeeper. Full walkthrough:
[macOS guide](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.1/docs/BETA-MAC-GUIDE.md).

## Windows (x64)

The recommended way is the **web app installed from Chrome or Edge**: open
<https://alambritodito.github.io/lila-modeler/app/> and choose **Install Lila Modeler**
([guide](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.1/docs/WINDOWS-PWA-TESTER-GUIDE.md)).

`Lila-Modeler-1.0.1-win-x64.exe` is also attached. It is **not signed** and **has not been
tested on a real Windows machine yet**. Windows SmartScreen will show “Windows protected your PC”:
click **More info**, then **Run anyway**. The
[Windows tester guide](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.1/docs/WINDOWS-TESTER-GUIDE.md)
walks you through it and ends with a report template.

## Verify the download

Put the installer and `SHA256SUMS` in the same folder. On macOS:

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS
```

On Windows, in PowerShell in that folder, compare the output with the `.exe` line of `SHA256SUMS`:

```powershell
Get-FileHash .\Lila-Modeler-1.0.1-win-x64.exe -Algorithm SHA256
```

## Known limitations

- **Unsigned**: no Developer ID on macOS (Open Anyway on first launch) and no signature on Windows.
  Signing is planned after 1.0.
- **macOS**: tested on macOS 27.0, Apple Silicon only. No Intel build.
- **Windows**: the installer is untested on a real Windows machine; the web app is the main channel.
- **Linux**: CI builds an AppImage, but it is untested and not attached.
- **Web**: Chrome is the browser that was tested; Safari is not a gate for 1.0.
- **Not simulated**: signal and escalation events (`E-NOSOP`).
- **No automatic updates**: the desktop app tells you when a newer version is on GitHub, but
  nothing is installed in place.
