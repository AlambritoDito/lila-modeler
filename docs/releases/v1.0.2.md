# Lila Modeler 1.0.2

A patch for 1.0.1 with fixes only, from the review of 1.0.0 as a Bizagi alternative. Results of
models that ran on 1.0.1 are unchanged, and 1.0.1 opens every file 1.0.2 writes. The web app on
Pages («Open the stable app»), the desktop installers below and the `@lila-modeler/engine` and
`@lila-modeler/mcp` packages on npm all move to this version.

## What is fixed

- **Agents can annotate and edit imported models** (#724). `lila process annotate`, `lila process
  edit` and the MCP tools `annotate_element` and `edit_process` used to refuse many Bizagi and BPMN
  MIWG files with "content that cannot be written back". They now keep what the reader cannot
  interpret (unresolved references, unknown elements, vendor extensions) exactly as written, and
  refuse only what cannot be kept safely, naming the construct, its line and the repair.
- **Structural errors show while you edit** (#722). A task no flow reaches, a gateway with no
  flows or a process with no start or end used to appear only on Run, with the element's id. They
  are now in the status bar, on the canvas and in the problems list as you draw, named by the
  element; the chips and the list entries take you to the element, on its own diagram.
- **Palette clicks inside a collapsed sub-process** (#721) create the figure in that sub-process
  instead of on the main diagram. Pool and Lane are disabled there.
- **Results map** (#718). Counters that are still `0/0` are not drawn, and the wait and bottleneck
  badge hangs under its own task, no wider than it, so it no longer covers the next element.

The full list is in the
[changelog](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.2/CHANGELOG.md).

## Reporting a problem

If something fails or reads wrong, use **Report a problem…**: on the desktop under **Help**, in the
web app in the app menu, or ⌘K / Ctrl+K and type «report». It opens GitHub's bug form with the
version and your platform already filled in; nothing is sent until you press **Submit**. Attach the
smallest `.lila` or `.bpmn` that shows the problem, and say what you expected.

## Install on macOS (Apple Silicon)

Download `Lila-Modeler-1.0.2-mac-arm64.dmg`, open it and drag the app to Applications. The app
is ad-hoc sealed but **not notarized**, so macOS blocks the first launch: double-click the app once,
then go to **System Settings ▸ Privacy & Security** and click **Open Anyway** next to the message
naming Lila Modeler, and confirm **Open**. On older macOS, Control-click the app ▸ **Open** ▸
**Open** works directly. Do not disable Gatekeeper. Full walkthrough:
[macOS guide](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.2/docs/BETA-MAC-GUIDE.md).

## Windows (x64)

The recommended way is the **web app installed from Chrome or Edge**: open
<https://alambritodito.github.io/lila-modeler/app/> and choose **Install Lila Modeler**
([guide](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.2/docs/WINDOWS-PWA-TESTER-GUIDE.md)).

`Lila-Modeler-1.0.2-win-x64.exe` is also attached. It is **not signed** and **has not been
tested on a real Windows machine yet**. Windows SmartScreen will show “Windows protected your PC”:
click **More info**, then **Run anyway**. The
[Windows tester guide](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.2/docs/WINDOWS-TESTER-GUIDE.md)
walks you through it and ends with a report template.

## Verify the download

Put the installer and `SHA256SUMS` in the same folder. On macOS:

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS
```

On Windows, in PowerShell in that folder, compare the output with the `.exe` line of `SHA256SUMS`:

```powershell
Get-FileHash .\Lila-Modeler-1.0.2-win-x64.exe -Algorithm SHA256
```

## Known limitations

- **Unsigned**: no Developer ID on macOS (Open Anyway on first launch) and no signature on Windows.
  Signing is planned after 1.0.
- **macOS**: tested on macOS 27.0, Apple Silicon only. No Intel build.
- **Windows**: the installer is untested on a real Windows machine; the web app is the main channel.
- **Linux**: CI builds an AppImage, but it is untested and not attached.
- **Web**: Chrome is the browser that was tested; Safari is not a gate for 1.0.
- **Not simulated**: signal and escalation events (`E-NOSOP`).
- **No automatic updates**: the desktop app tells you when a newer version is on GitHub, but
  nothing is installed in place.
