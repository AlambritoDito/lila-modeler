# Lila Modeler 1.0.0-rc.1

The release candidate for Lila Modeler 1.0.0. From here to 1.0.0 only bug fixes go in: please use
it with your own processes for a week or two and tell us what breaks. The web app on Pages («Open
the stable app»), the desktop installers below and the `@lila-modeler/engine` and
`@lila-modeler/mcp` packages on npm all move to this version.

## For RC testers

If something fails or reads wrong, use **Report a problem…**: on the desktop under **Help**, in the
web app in the app menu, or ⌘K / Ctrl+K and type «report». It opens GitHub's bug form with the
version and your platform already filled in; nothing is sent until you press **Submit**. Attach the
smallest `.lila` or `.bpmn` that shows the problem, and say what you expected. Diagrams exported
from Bizagi are especially welcome.

## What is new since beta.26

beta.27 to beta.29 were interim versions (no installer published); this is what they and the
release candidate added. The exact per-version list is in the
[changelog](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.0-rc.1/CHANGELOG.md).

- **More of BPMN simulates** (ADR-033). Elements that used to stop the run with `E-NOSOP`:
  - the **loop marker** on a task: a fixed number of times, or again with a probability, capped by
    the diagram's `loopMaximum`;
  - **multi-instance** tasks, parallel and sequential, with N from the diagram or the scenario;
  - **error boundary events**, with a probability per completion of the activity, and a **timer
    boundary on a sub-process**;
  - **message** start and end events and **none and message intermediate throw** events.

  Simulate offers the new fields (Loop and Instances in Times, error probability in Routes) and the
  scenario spreadsheet carries them. Signal and escalation events are still not simulated.
- **Your files keep working.** Every `.lila` written by a released version opens and runs, including
  the ones saved before #613 fixed loose-diagram names; frozen files from beta.29 are checked on
  every test run.
- **Two apps on Pages.** «Open the stable app» only changes with a Release; «Beta: what comes next»
  follows `main`. They keep separate recovered projects.
- **Phone and tablet viewer** (beta.27): the diagram with your fingers, what each element does and
  the heat map of the last saved run, read-only.
- **Report a problem** (beta.28) opens GitHub's bug form with the version filled in, also from the
  phone viewer (beta.29).
- **Agents** (beta.28, beta.29): through MCP and the CLI an agent models what the simulator runs
  (escalation timers, waits, terminate ends, several starts, default flows, lanes, notes, data
  objects, extended attributes), renames and deletes processes and scenarios, patches scenarios,
  writes the event log and the comparison workbook, and colours the diagram with a stored run. See
  [docs/MCP.md](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.0-rc.1/docs/MCP.md).
- Lila Light and Lila Dark reach WCAG AA contrast where they fell short.

Results of models that do not use the new elements are unchanged.

## Install on macOS (Apple Silicon)

Download `Lila-Modeler-1.0.0-rc.1-mac-arm64.dmg`, open it and drag the app to Applications. The app
is ad-hoc sealed but **not notarized**, so macOS blocks the first launch: double-click the app once,
then go to **System Settings ▸ Privacy & Security** and click **Open Anyway** next to the message
naming Lila Modeler, and confirm **Open**. On older macOS, Control-click the app ▸ **Open** ▸
**Open** works directly. Do not disable Gatekeeper. Full walkthrough:
[macOS guide](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.0-rc.1/docs/BETA-MAC-GUIDE.md).

## Windows (x64)

The recommended way is the **web app installed from Chrome or Edge**: open
<https://alambritodito.github.io/lila-modeler/app/> and choose **Install Lila Modeler**
([guide](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.0-rc.1/docs/WINDOWS-PWA-TESTER-GUIDE.md)).

`Lila-Modeler-1.0.0-rc.1-win-x64.exe` is also attached. It is **not signed** and **has not been
tested on a real Windows machine yet**. Windows SmartScreen will show “Windows protected your PC”:
click **More info**, then **Run anyway**. The
[Windows tester guide](https://github.com/AlambritoDito/lila-modeler/blob/v1.0.0-rc.1/docs/WINDOWS-TESTER-GUIDE.md)
walks you through it and ends with a report template.

## Verify the download

Put the installer and `SHA256SUMS` in the same folder. On macOS:

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS
```

On Windows, in PowerShell in that folder, compare the output with the `.exe` line of `SHA256SUMS`:

```powershell
Get-FileHash .\Lila-Modeler-1.0.0-rc.1-win-x64.exe -Algorithm SHA256
```

## Known limitations

- **Unsigned**: no Developer ID on macOS (Open Anyway on first launch) and no signature on Windows.
  Signing is planned after 1.0.
- **macOS**: tested on macOS 27.0, Apple Silicon only. No Intel build.
- **Windows**: the installer is untested on a real Windows machine; the web app is the main channel.
- **Linux**: CI builds an AppImage, but it is untested and not attached.
- **Web**: Chrome is the browser that was tested; Safari is not a gate for 1.0.
- **Not simulated**: signal and escalation events (`E-NOSOP`).
- **No automatic updates**: the desktop app tells you when a newer version is on GitHub, but
  nothing is installed in place.
